## 1. 环境搭建与版本管理

> 新手 80% 的时间浪费在这里。搞懂版本对应关系，能省掉后面几个月。

### 必学

**虚拟环境**

- [ ] 为什么**必须**用虚拟环境（依赖冲突、A/B 版本共存、可复现）
- [ ] 三条路线的定位：`venv`（标准库）、`conda`（管二进制与 CUDA）、`uv`（快且现代）
- [ ] 创建 / 激活 / 退出 / 删除一个环境
- [ ] 多环境切换与「我在哪个环境里」的确认习惯

**GPU 版本对应（最关键的一节）**

- [ ] 四层关系：**显卡驱动 → CUDA 运行时 → cuDNN → PyTorch 编译版本**
- [ ] 驱动版本决定能用的 CUDA **上限**（向下兼容）
- [ ] `nvidia-smi` 右上角的 CUDA 版本 ≠ `nvcc --version`，两者分别代表什么
- [ ] 看懂 PyTorch 官网安装选择器，并能解释生成的 pip 命令
- [ ] 为什么**不能**直接 `pip install torch` 就以为装上了 GPU 版
- [ ] 误装 CPU 版的典型症状（`torch.cuda.is_available()` 为 False）
- [ ] 验证安装的标准命令：
  `python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.device_count())"`
- [ ] CPU-only 与 GPU 版本混装后的清理方式

**网络与平台**

- [ ] 国内镜像源配置（pip / conda），以及**镜像不提供 GPU 轮子**的坑
- [ ] WSL2 与 Windows 原生各自适合什么场景
- [ ] 显存监控：`nvidia-smi` 的常用参数与 `watch` 刷新
- [ ] 环境导出与复现：`requirements.txt` / `environment.yml` / `uv.lock`
- [ ] `pip freeze` 的局限（会把无关包一起导出、丢失来源信息）

### 练到什么程度

**在一台干净机器上从零把 GPU 版 PyTorch 装好并验证成功**，全程能说出每一步为什么。

## 2. 深度学习框架使用

> 目标是「不用抄模板也能写出训练循环」。

### 必学

**基础机制**

- [ ] Tensor 与自动求导：`requires_grad`、`backward()`、计算图的构建与释放
- [ ] `nn.Module` 的约定：`forward`、`parameters()`、`state_dict()`
- [ ] 一个训练循环的五个步骤：清零梯度 → 前向 → 算损失 → 反向 → 更新
- [ ] `optimizer.zero_grad()` 不做会发生什么
- [ ] `torch.no_grad()` 与 `inference_mode()` 的区别与用途
- [ ] 保存与加载：`state_dict` vs 整个模型对象（为什么前者更好）

**数据与设备**

- [ ] `Dataset` / `DataLoader` 的职责划分
- [ ] `num_workers` 的坑（Windows 下 `spawn`、需要 `if __name__ == '__main__'`）
- [ ] `pin_memory` 与 `non_blocking` 为什么能加速
- [ ] 设备管理：`.to(device)` 的位置、模型与数据的设备必须一致
- [ ] 混合精度训练：`autocast` + `GradScaler` 分别在做什么

**性能与稳定**

- [ ] 显存泄漏的常见原因：保留了带梯度的张量、未 `detach`、累积在列表里
- [ ] 梯度累积与梯度检查点分别省什么、代价是什么
- [ ] 训练复现性：随机种子、`cudnn.deterministic` 与性能的取舍
- [ ] 为什么 GPU 利用率低：常见三种原因（数据加载瓶颈 / 同步点 / 小 batch）
- [ ] 用 `torch.profiler` 看一次真实的时间分布

### 练到什么程度

**手写一个完整训练循环**（训练 + 验证 + 保存最佳权重），并解释每一步在干什么。

## 3. 大模型工具链

> 这一节的目标是「给我一个开源模型，我能从头到脚自己跑一遍」。

### 必学

**加载与推理**

- [ ] `AutoModel` / `AutoTokenizer` 的加载流程与背后发生了什么
- [ ] `from_pretrained` 关键参数：`torch_dtype`、`device_map`、`attn_implementation`
- [ ] Tokenizer 的实际输出：`input_ids` / `attention_mask` 长什么样、为什么需要 mask
- [ ] 生成参数：`max_new_tokens`、`temperature`、`top_p`、`do_sample` 的作用组合
- [ ] `apply_chat_template` 的正确用法，以及它与 `tokenizer.encode` 的区别
- [ ] 分片权重 / `safetensors` 与 `.bin` 的区别

**模型与数据的获取**

- [ ] `huggingface-cli` 下载指定文件（而不是整个仓库）
- [ ] 国内镜像 `HF_ENDPOINT`（hf-mirror）与 ModelScope 的用法
- [ ] `load_dataset` 的流式模式（`streaming=True`）解决什么问题

**微调与评测工具**

- [ ] 训练框架定位：`Trainer` / `Accelerate` / `DeepSpeed` / `LLaMA-Factory`
- [ ] `peft` 库：LoRA 配置项 `r`、`alpha`、`target_modules` 的实际写法
- [ ] 量化加载：`bitsandbytes` 的 4-bit 配置、GPTQ / AWQ 模型的使用差别
- [ ] 评测工具：`lm-evaluation-harness` 之类跑通一次

### 练到什么程度

独立完成一次全流程：**下载开源模型 → 本地推理 → LoRA 微调 → 导出**，每步失败时知道去哪查。

## 4. 部署与服务化

> 从「我这儿能跑」到「别人能访问」，中间隔着一整套工程。

### 必学

**本地跑起来**

- [ ] 三件套定位：Ollama（开箱即用）/ llama.cpp（底层可控）/ LM Studio（图形界面）
- [ ] GGUF 格式与量化等级（`Q4_K_M` 这类命名怎么读）
- [ ] HF 权重 → GGUF 的转换流程
- [ ] 本地跑不动时的正确降级顺序（降量化等级 → 换更小模型 → 上 CPU）

**服务化**

- [ ] 推理框架选型：vLLM / SGLang / TGI 的定位差异
- [ ] **OpenAI 兼容 API** 为什么重要（换后端不改客户端）
- [ ] 显存规划：权重 + KV Cache + 激活，各自怎么估
- [ ] vLLM 关键参数：`gpu_memory_utilization`、`max_num_seqs`、`max_model_len`
- [ ] 容器化部署与 GPU 透传（`--gpus`、驱动与容器运行时）
- [ ] 反向代理、鉴权、限流这三件上线必备

**观测**

- [ ] 关键指标：GPU 利用率、显存占用、吞吐（tokens/s）、**P95 延迟**
- [ ] 压测：并发上去了会先坏在哪

### 练到什么程度

把任意一个开源模型用 **vLLM 起成 OpenAI 兼容服务**，并能说清「显存是怎么被用满的」。

## 5. 调试与排错

> 这一节决定你是「修环境的人」还是「重装环境的人」。

### 必学

**通用方法**

- [ ] 读报错的正确顺序：**第一行（错误类型）与最后一行（具体消息）**，中间是调用栈
- [ ] 用**最小可复现脚本**定位问题，而不是在完整项目里试
- [ ] 先确认「问题是代码、环境还是网络」
- [ ] **别在没读懂报错时就重装环境**（重装会掩盖根因，下次还会遇到）

**高频故障**

- [ ] **CUDA OOM 的排查顺序**：降 batch / 序列长度 → 查是否泄漏 → 开梯度检查点 → 上量化
- [ ] OOM 报错里的数字怎么读（已分配 / 保留 / 试图分配多少）
- [ ] 版本冲突定位：`pip check`、看冲突包的依赖树
- [ ] 外网下载失败的排查顺序：代理 → 镜像源 → DNS → 证书
- [ ] 「本地能跑、服务器不能跑」的差异清单（版本 / 显卡 / 权限 / 路径）

### 练到什么程度

遇到 OOM 或版本冲突，**能在 15 分钟内定位到原因**，而不是靠重装环境碰运气。

## 6. 工程习惯与记录

> 本目录存在的意义：**同一个坑不踩第二次。**

### 必学

- [ ] 踩坑笔记的命名：`工具名-问题简述.md`（例 `bitsandbytes-Windows-安装失败.md`）
- [ ] 每条踩坑笔记的**四要素**：现象、环境版本、根因、解法
- [ ] 环境版本随笔记一起记（否则半年后无法判断解法是否还适用）
- [ ] 命令要能直接复制执行，**不要把路径写死成自己机器的**
- [ ] 维护本目录的「常用命令速查」（环境验证、训练启动、显存查看）
- [ ] 定期把重复出现的坑**合并成一篇**，而不是散落十几篇
- [ ] 清楚哪些东西**绝不提交**：密钥、模型权重、大数据集、虚拟环境（见仓库 `.gitignore`）

### 练到什么程度

半年后同一个坑再遇到，**能在自己的笔记里 1 分钟内搜到解法**。

## 最小必学清单

如果你只想先学最核心的：

1. 用虚拟环境隔离依赖（`venv` 或 `conda` 起步即可）
2. **驱动 → CUDA → cuDNN → PyTorch 的版本对应关系**
3. 验证 GPU 可用性的那条标准命令
4. 手写一次完整训练循环（含验证与保存）
5. 看懂 OOM 报错并知道排查顺序
6. `AutoModel` + `AutoTokenizer` + `apply_chat_template` 跑通推理
7. 用 `peft` 做一次 LoRA 微调
8. 显存规划：权重 + KV Cache 怎么估
9. `nvidia-smi` 与 GPU 利用率低时的三种排查方向
10. **踩坑笔记四要素**：现象、环境、根因、解法

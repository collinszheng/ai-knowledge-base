# 07 · 可复用资产

> 从项目里沉淀下来、**下次可以直接抄**的东西。

01–06 回答的是「怎么学、怎么用 AI 写软件」；这里是那套方法跑完之后**留下的产物**。所以 07 不在学习路线上 —— 它是一本随时查、随时取用的手册，不是要按顺序读完的章节。

## 放什么

判断标准只有一条：**换个项目还能不能用。**

- ✅ 真正好用的提示词（附失败版本作对比）
- ✅ 规则文件骨架（`AGENTS.md`、`.cursor/rules/*.mdc`）
- ✅ 可复制的代码 / 配置片段（连同它解决的具体问题）
- ✅ 排错解法：现象 → 根因 → 解法
- ✅ 重复做过三次以上的工作流步骤
- ✅ 花了时间才搞明白、下次不想再花的踩坑结论

## 不放什么

| 这类内容 | 该去哪 |
| --- | --- |
| 只对某一个项目成立的背景、取舍、演进 | [01 · AI辅助工程](../01-AI辅助工程/) 下的 `项目-<项目名>.md` |
| 「该学什么、练到什么程度」 | 对应分区的 `学习清单.md` |
| 学习过程中的推导与笔记 | 对应学习分区（02–06） |
| 临时草稿、半成品 | 先留在自己机器上 |

## 怎么把项目里的东西变成这里的一页

别打算「整理一下项目再开始」，那件事永远不会开始。改成：**做到一半，回头问三句。**

1. 下次还会遇到吗？——不会，跳过
2. 换个项目还能用吗？——不能，它属于项目档案（见上表）
3. 不看上下文能看懂吗？——不能，说明还没提炼完，再补两句

三个都「是」，就当场记一条。**当场记**是关键：事后再补，细节全忘了。

## 文件命名

扁平放在本目录下，**不建子目录** —— 站点的侧边栏只扫分区目录的一级 `.md`，放进子目录就看不见了。

格式：`<类别>-<具体点>.md`，靠文件名前缀分组。

当前 5 个类别。切法是**按「拿到一个东西时它是什么形态」**，不按技术栈 —— 技术栈从 Android 换成 Web，这五个类别一个字都不用改：

| 前缀 | 放什么 | 判断依据 |
| --- | --- | --- |
| `规则-` | 让 AI / 协作者守规矩的东西 | 落点是**约束行为** |
| `文档骨架-` | 可以整套复制的文档结构与格式 | 落点是**一份文档怎么长** |
| `验证-` | 把验证链路脚本化：脚本骨架 + 验证纪律 | 落点是**怎么确认它真的对** |
| `配置-` | 可以直接粘贴的构建 / 签名 / 忽略配置 | 落点是**配置文件里的几行** |
| `坑-` | 一句话结论 + 机制 + 复现方式 | 落点是**不知道就会踩** |

> 这 5 个是从第一批真实产物里归纳出来的，不是先编好再往里塞。第二个项目可能会加类（比如「提示词」）或并类 —— 到时候按同样的判断标准调整，别硬塞。

## 一页资产长什么样

```markdown
# <类别>-<具体点>

> 一句话：什么时候该用它、解决什么问题。

## 来源
哪个项目、当时要解决什么。链到项目档案。

## 怎么用
可以直接复制的原件或步骤。

## 边界
什么时候别用、已知的坑。

## 相关
衍生自哪个学习分区，或相关的资产页。
```

第一批三页落地之后追加的两条经验：

- **正文不要抄第二份。** 项目里已经有脚本 / 配置的，这里写「骨架 + 为什么」，正文留在项目里 —— 否则两份会慢慢漂移（见 [验证-Android 验证回路](./验证-Android验证回路.md)）
- **「来源」链到项目档案。** 让人能顺着往回走，看它当时是在什么约束下做出来的

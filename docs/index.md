# AI Knowledge Base

> 这个仓库只服务一个目标：**用 AI 把软件项目做得更快、更好**。
>
> 所以主线不是「理解 AI 的一切」，而是「指挥 AI 写代码，并判断它写得对不对」。大模型原理、数学基础这些，只在真正卡住的时候按需回补。

**写作原则：** 能用自己的话讲清楚，才算真的学会。所以这里的每篇笔记都尽量做到「结论先行 + 推导过程 + 可运行的例子 + 踩坑记录」。

::: tip 忘了怎么操作？
从写笔记、提交、发布，到构建失败和死链怎么排查，日常操作全收在[**使用手册**](/使用手册/)里。
:::

## 建议的学习路线

这一节回答一个问题：**以「用 AI 辅助开发软件项目」为目标，先学什么、后学什么。**

```text
第 1 步 · 先把它用起来（第 1 周）
  工具操作 → 提示词与任务拆解 → 在项目里配好 AGENTS.md
        ↓
第 2 步 · 建立验证回路（第 2–4 周）        ★ 分水岭
  类型检查 / lint / 测试 / 构建 → 让 AI 自己看得到这些信号
        ↓
第 3 步 · 补软件工程底子（第 2 个月）
  模块边界 → 代码审查 → 重构 → 提交粒度与版本控制
        ↓
第 4 步 · 工程化，把个人习惯变成流程
  自动化与集成 → 安全与合规 → 团队协作规范 → 评估与持续改进
        ↓
第 5 步 · 按需回补（这些都不是前置知识）
  工具与环境（随手查） → AI 应用开发（要给项目加 AI 功能时）
  → 大模型原理 / AI 基础（卡住了再补） → 论文笔记（想做研究时）
```

**为什么这样排**

- 这个目标的瓶颈不在 AI 知识上，在**软件工程判断力**上 —— AI 只是个放大器：判断力好，它让你快十倍；判断力差，它让你以十倍速度制造混乱。
- 没有**确定性反馈回路**（类型检查、lint、测试），你根本分不清 AI 的输出是好是坏，很容易掉进「看着像对的 → 上线炸掉 → 不再信任 AI」的循环。这一步技术含量不高，但它是「AI 玩具」和「AI 生产力」的分界线，值得排在原理之前。
- 先啃原理的**回报周期太长**：花几个月学数学和 Transformer 推导，写业务代码时基本用不上。

**真正需要知道的 AI 概念只有四个：** token 与上下文窗口、温度与采样、幻觉为什么会发生、KV Cache 占多少显存。直觉级就够，不必手推注意力。

> **最大的坑：** 按 01 → 06 的编号从头学完再动手 —— 半年后你还在学数学，一个项目都没做完。正确的启动方式是：**今天就用 AI 做一个真东西，在卡住的地方回补知识。**

## 怎么用这个站

- **左侧边栏**按分区列出全部笔记；进到某个分区后，底部的「其他分区」可以快速跳走
- **右上角搜索**是全文检索，中文按词切分（搜「注意力」能找到「注意力机制」），不需要联网
- 每篇笔记右侧有**本页目录**，页脚有**最后更新于**和上一篇 / 下一篇
- 想改哪篇，点页脚的「在 GitHub 上编辑此页」直接改，改完提交就会自动重新发布
- 忘了某个操作怎么做（怎么加分区、图片放哪、构建失败了怎么办），翻[**使用手册**](/使用手册/)
